# OpenSay 模板开发

把参考片逐镜复刻成可复用模板（原片每一类能还原的镜头都成为模块，并还原那一镜），或把具体镜头的表达缺口变成同风格独立模块。动态模板保存在本地 OpenSay；本 Skill 只保存开发方法、交接契约和必要检查工具。**所有新模板与新增/修改片段都必须符合同一 OpenSay 消费规范并通过准入检查**，见[统一消费准入](references/consumer-admission.md)；字符剧场只是首个参考实现。

## 执行范围

- 模板创建、扩展与写库只由 **Codex 或 Claude Code** 执行。其他 Agent 可消费已发布模板、整理素材、输出请求单；不得自行接管模板开发或静默换成较弱模型。
- 技能真源为 `~/.codex/skills/opensay-template-builder/`；Claude Code 使用其专用入口 `~/.claude/skills/opensay-template-builder/`。不安装到共享 `.agents/skills`，不修改其他客户端的全局配置。
- 开始模板写入前运行 `python3 scripts/host_guard.py`（路径相对本 Skill），把报告保存到本期工作目录。报告默认只创建新文件；刷新既有同 Schema 的宿主报告必须显式加 `--refresh-report`。不得把输出放进模板库；自定义库根用 `--library-root` 补充保护。无法识别宿主时输出交接请求，保持模板只读；已有可信宿主上下文时可记录该上下文并继续用户已授权的工作，不重复索要许可。
- `host_guard` 的进程/环境证据只能防误用，**不是认证或文件系统 ACL**。同一 OS 用户的其他程序仍可能读取技能或修改库。真正独占写权限需要另外的系统权限边界，不能把此 Skill 宣称为硬隔离。
- 保持当前已配置的模型，不静默降级。记录宿主实际暴露的模型标识及证据；未暴露就写 `unknown`，不能用自报型号或客户端名称伪造“顶级模型认证”。用户已授权在当前 Codex/Claude Code 执行的工作不因无法读取内部型号而增加确认门禁；画面质量仍必须实测。

## 选择工作模式

| 请求 | 读取 | 交付 |
| --- | --- | --- |
| 根据博主/参考片制作新模板 | **先读 [从参考片逐镜复刻](references/replicate-reference.md)（主流程）**，再读 [从参考创建模板](references/create-template.md)（合同、声音、归档）、[声音层交付](references/audio-design.md) | 本期工作目录：逐镜清单、覆盖表、复刻规格、同类素材、对照报告；`opensay/<template>/` 中的源码、运行入口、视听风格规范、音效映射 `audio/sfx-map.v1.json`（新音色代码合成进库根 `sfx/`）、能力声明、真实有声模块预览 |
| Sticker 编排不通过、重复选型或镜头无法表达 | [扩展现有模板](references/extend-template.md)、[声音层交付](references/audio-design.md) | 已验证的新模块/必要修复、受影响声音事件与混音、本期同步动态草稿、当前能力版本与回归记录 |

没有请求单时可从用户明确输入生成，不要求用户填写内部 JSON。跨 Agent 交接使用 [请求 Schema](references/template-request.schema.json)，执行 `python3 scripts/validate_request.py /absolute/request.json` 检查路径、哈希和镜头绑定。校验结构或脚本返回成功不代表风格/画面已验收。

## 两种模式都必须保持的结果

1. 新建模板按[逐镜复刻](references/replicate-reference.md)：原片里每一类能还原的镜头都做成模块（覆盖），每个模块按从原片全分辨率帧量出的规格还原那一镜（还原），并用「原片 | 模块」对照报告证明；覆盖表和对照报告不全不能声称完成。扩展模板时同样先核对实际参考/模板源码、已有预览与本期内容，区分路由错误、缺素材、时序问题和真实模块缺口；只有最后一种需要新模块。不要把每个口头比喻都升级成新镜头需求。
2. 新模块必须可独立初始化、替换声明的素材、按目标时长和可信语义事件渲染，支持任意跳时与重复渲染，没有上个镜头残留。源码阶段目录只是研究/复用候选；截取时间窗、换名称、补能力 JSON 不等于独立模块完成。
3. 保持模板的构图语言、字体、配色、描边、角色、缓动、形变、运镜、节奏和转场。风格一致不能只看静态截图；将已有认可动作与新动作并排播放检查。无真人时主动重排，不留人像空框。
4. 按真实声音安排入场、信息变化、阅读与退场。原声不变速、不循环；缺词级证据不能把本期正式制作标为就绪，测试预览的句级锚点必须显式标注限制，不均分或猜词时刻。使用与本期完整正式动态预览相同的 renderer、参数、素材与 events 生成本期完整镜头草稿，不再把循环模块参考和独立试听当作本期同步预览。
5. 用不同内容验证复用（构造与原片同种类的测试素材，不用原片的文字和画面）。实际显示什么就声明什么；不能由模板级字段推断所有模块都支持 Logo/图片/视频/真人。完整品牌名、否定词、数值单位不能为了塞进模板而丢失。
6. 模板一文件夹一真源，默认 `~/Desktop/opensay/<template>/`，允许显式指定其他根目录。不建立全局 registry、adapter、模块合同目录，不把模板副本塞进 Skill。沿用模板已有源码组织和真实运行技术。
7. 新模板、扩展和修复都更新本模板 `capability/consumer.v1.json` 与同一消费运行入口，保存当前源码/合同绑定的验证证据并运行 `scripts/check_consumer.py`。缺字段、超容量、不支持的素材/出镜/输出和缺必需事件必须报可修复错误；未验证能力不得只改状态为可制作。
8. 参考的 **BGM 与音效是默认必交付项**：分析其声音特征、源片时间、动作触发、响度层级和 duck/fade，交付可替换、可单独试听和静音的声音层及真实有声预览。原混音、旁白、伴奏和事件音效必须分开声明；优先从源片提取或分离，残留旁白/底乐如实记录，不能把混音命名成纯净 BGM/SFX。缺素材或分离不净就标具体缺口；同风格替代须明确来源和差异，不能静默替换或只交无声模板。参考本来无 BGM/音效时记录可核验的缺席，不强行配乐。详细合同与验收见 [声音层交付](references/audio-design.md)。

## 交回 Sticker

在模板目录内维护当前源码、视听风格规范、`capability.json`、参数/素材合同、`audio/sfx-map.v1.json` 与验证预览（音效在库根 `sfx/`，配乐在库根 `bgm/`）。能力声明同步真实 renderer、语义适用范围、文本容量、布局/动作签名、素材/出镜方式、时长和 beat 约束，以及实际支持的 BGM/SFX 槽位、混音控制、声音来源与质量、验证状态。源片混音或分离文件不能仅凭已入库就变成有授权可投产素材。

修改前留可恢复版本；先在本期工作目录准备变更和实际预览，再更新模板版本与哈希。保留来源说明、字体等依赖许可证。已批准工程绑定旧版本/哈希，不随库更新自动替换。

返回模块 ID、变更原因、来源版本、能力/源码及音频资产哈希、音画测试结果、可播放的有声预览、映射回本期的真实镜头与剩余缺口。**机器检查、画面/听音自审、用户批准分别记录**，不代填用户确认。已有用户授权继续复用；本次本地参考样片已明确授权的声音复用不增加确认门禁。扩展完成回到同一轮完整正式动态预览与编排审核；覆盖完整后一次确认，再复用已审媒体执行 QC、发布包及既有投递，不另加逐模块、样片或重复同版全片审批。
