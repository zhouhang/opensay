# 从参考片逐镜复刻模板

新建模板的主流程。两个目标同时成立才算完成：

1. **覆盖**：原片里每一类能还原的镜头，都成为一个模块。
2. **还原**：每个模块还原原片那一镜的构图、尺寸、字体字号、配色、节拍、动作、机位、质感、画面机制和进出衔接；只有文字、数字、素材和少量颜色变体做成参数。

合同、声音、归档、准入仍按 [从参考创建模板](create-template.md)、[声音层交付](audio-design.md)、[统一消费准入](consumer-admission.md)。

## 交付物（都放本期工作目录；任何一项缺失或有空字段，就不能声称模板完成）

| 步骤 | 产物 | 完成标准 |
| --- | --- | --- |
| 1 逐镜清单 | `inventory/segments.json`、`contact.html` | 每段的 `type_id / what / beats / reproduce / notes` 都已填写；切错的段已拆分或合并 |
| 2 覆盖表 | `inventory/coverage.md` | 每类镜头对应：原片段 ID、能否还原、模块 ID 或缺口原因；新增的通用片段单独列出 |
| 3 复刻规格 | `specs/<type>.md`，加上 `specs/<type>/measure/` | 下面「规格必填项」逐项有数值，数值来自原片全分辨率帧 |
| 4 同类素材 | `materials/` 和 `materials/README.md` | 每个模块有「对照套」「变化套」两套内容，不含原片的文字和画面 |
| 5 模块 | 模板目录 | 一类镜头一个模块；事件就是原片的节拍 |
| 6 对照报告 | `fidelity/report.html`、`fidelity/pairs.json` | 每个模块：自动指标在阈值内，且评审结论为「接近」 |
| 7 准入 | 准入回执和审核页 | 按 consumer-admission.md；审核页链接对照报告 |

## 1 逐镜清单

```sh
python3 <skill>/scripts/segment_reference.py --video /abs/ref.mp4 --out /abs/work/inventory
```

脚本按「硬切或整页画面变化」切段，并导出每段三张全分辨率关键帧。这只是起点：

- 每一段都要打开全分辨率关键帧（必要时用第 3 步的逐帧图）再填写。不要用抽帧缩略图或接触表（contact sheet）描述镜头，缩略图会把「屏幕里的 3D 内容」看成「屏幕倾斜」。
- 一段里含两个镜头时拆开，例如 1 秒提问卡接一个场景。误切的段要合并。
- 版式相同、动作机制相同的段归为同一 `type_id`，内容不同也算同一类。机制不同就是不同类，颜色相同也一样。
- `reproduce` 取下面五种之一：
  - `code`：代码可画
  - `code+user-material`：画面主体是用户自己的素材
  - `webgl`：需要 3D 光照、粒子、景深
  - `external-data`：依赖外部数据，如地图服务、实时数据
  - `live-footage`：实拍画面

## 2 覆盖表

- `code`、`webgl`、`code+user-material` 三类镜头都必须有模块。
- `external-data`、`live-footage` 写明缺口和需要什么；也可以做成素材承载模块，但要写清楚承载的是用户素材，不是原片画面。
- 一个模块只算覆盖它真正还原的那一类。不能用一个通用模块顶几类原片镜头，也不能拿已有模块"差不多"顶替。
- 真人、录屏、结尾号召这类原片里没有的片段可以加，但在覆盖表里单独列为「新增通用片段，非原片镜头」，不计入覆盖。

## 3 复刻规格（每类镜头一份）

```sh
python3 <skill>/scripts/measure_segment.py --video /abs/ref.mp4 --start 32.0 --end 36.2 --out /abs/work/specs/<type>/measure
```

脚本给出节拍时间、整画面运动占比、静止占比、内容包围盒、主色、这一段的声音起音点（`audio_onsets`），并按每秒 10 帧导出全分辨率帧。位置、字号、运动路径从这些帧上读取。切点、闪白这类只持续一两帧的东西，用 30fps 逐帧再看一遍（`ffmpeg -vf fps=30`），10fps 会漏。

**规格必填项**（某项原片里没有，就写「无」）：

1. **出处**：段 ID、原片时间、关键帧路径。合同里写的原片时间必须和这里一致。
2. **画布与背景**：底色或渐变（取色值）、纹理、光晕位置。
3. **元素表**：每个元素在 1920×1080 下的位置和尺寸、字体类别、字号、字重、颜色、圆角、描边、阴影。
4. **节拍**：原片的动作序列。每个动作起一个名字（例如 type、swap、race、settle），写明相对镜头开始的秒数。模块的事件名和默认位置照抄这里。
5. **动作**：每个元素的起止状态、时长、缓动方式，从逐帧位置读出。
6. **机位**：静止、推、移、倾斜、环绕之一，以及幅度。
7. **画面机制**：画面由什么驱动（打字进度、数据、代码、时间、物理）。模块必须用参数驱动同样的变化，不能换成一张图片或一段视频。
8. **进出衔接**：从上一镜怎么接进来，怎么接到下一镜，例如硬切、缩成一点、推进、拉远、标题保持不动。
9. **质感**：颗粒、景深、发光、模糊、阴影、色差。
10. **时长**：理想时长取原片这一镜的时长；最短是动作做完需要的时间；最长要实测，不凭感觉写：在声明的最长时长下渲染一次，超过原片这一镜长度的部分必须一直有动作（每 0.3 秒至少 0.4% 的 96×54 缩略图像素变化超过 10 级）。原片在这一镜里自己的动作能延续的就延续（慢推、氛围循环、轨迹重画）；延续不了就把最长改小。不长于原片这一镜的用例，可以像原片一样静着结束。
11. **技术**：Canvas 2D、WebGL（three.js）或视频遮罩。
12. **未还原项**：做不到的部分和原因。覆盖表里要同步标注。
13. **声音**：这一镜原片在哪些节拍有音效（用 `audio_onsets` 对照画面动作：大字落下、打字、切卡、数字滚动……），映射到库根 `sfx/` 的哪个 id；库里没有的音色写明要新合成什么（见 [声音层交付](audio-design.md)）。原片音频只用来定位，不提取进库；没有人耳听审就写「听审 pending」。

## 4 同类素材

- 不用原片的文字和画面，截帧、抠图、转写的文案都不行。
- 按原片素材的**种类**自己构造：
  - 界面截图：用 HTML 渲染后截图
  - 插画、图标：用代码画
  - 视频：用 ffmpeg 合成
  - 文案：自己写
- 种类、数量、长宽比、色彩丰富度要和原片那一镜一致。原片是 30 张高饱和缩略图，就造 30 张高饱和缩略图，不能用色条或噪点代替。
- 每个模块准备两套内容：
  - **对照套**：结构对齐原片那一镜（条数、字数、节拍间隔相同），但文字和素材都换掉。
  - **变化套**：条数、字数、时长都不同，用来验证通用性。
- `materials/README.md` 写明每份素材是怎么生成的。

## 5 实现

- 一类镜头一个模块。模块事件 = 规格里的节拍名，默认位置按原片比例，理想时长 = 原片时长。
- 文字、数字、素材、颜色变体做参数。构图、动作、机位、质感按规格写死，不留给使用者调。
- 渲染技术按原片选：
  - 有 3D 光照、粒子、景深时用 WebGL。本机 three.js 在 `~/node_modules/three/build/three.module.js`（r170，MIT）。复制到模板的 `modules/vendor/`，并把许可证放进 `licenses/`。
  - 确定性规则：
    - 不用 `Math.random` 和 `Date`，所有动画只由时间 t 决定。
    - WebGL 渲染器开 `preserveDrawingBuffer: true`。
    - 每帧渲染后用 `drawImage` 合成到主画布。
    - 用同一时刻重复渲染的像素哈希验证可复现。
- 进出衔接按规格做：硬切、缩点、推进这些写进模块的入场和出场，或者走编译器提供的上一镜信息（`continuity`）。
- 原片用到的字体：本地已有、许可允许的直接用；没有的，写进规格的未还原项，并问用户能不能下载。

## 6 对照门槛

对照套每个用例存成一份 shot 请求 JSON，用库里现成的渲染入口出片（和成片同一条渲染路径，不另写渲染脚本）：

```sh
python3 /abs/opensay/.opensay/opensay.py render-shot --template /abs/opensay/<template> --request /abs/work/cases/<case>.json --out /abs/work/renders/<case>.mp4
```

然后写 `fidelity/pairs.json`（格式见脚本头部说明），运行：

```sh
python3 <skill>/scripts/fidelity_report.py --pairs /abs/work/fidelity/pairs.json --out /abs/work/fidelity
```

- 脚本生成「原片 | 模块」并排视频、同进度对帧图，以及两边相同口径的指标：时长、每 10 秒画面变化次数、静止占比、整画面运动占比、最后不动的比例、填充度。超出阈值会自动标记。
- 评审要逐组看并排视频和对帧图，按规格必填项逐项写出看到的差距，写进 `pairs.json` 的 `review`，并给出结论：
  - `close`：接近
  - `partial`：部分对上
  - `far`：差距大
- 不写「整体不错」这类判断。
- **只有自动指标没有标记、并且评审结论是 `close`，模块才算通过。** `partial` 和 `far` 回到第 3 步或第 5 步，改完重新出报告。
- 阈值在脚本 `LIMITS` 里。新模板先用原片里同一类镜头的几次出现互相比对，确认阈值不会把原片自己判成不像。
- 被标记了先查差在哪，再改代码：

  ```sh
  python3 <skill>/scripts/diff_regions.py --ref /abs/ref.mp4 --start 49.0 --end 52.0 --mod /abs/work/renders/<case>.mp4 --sample 2.5
  ```

  它按 0.1 秒逐步、按 3×3 区域并排列出原片和模块各自变了多少（`<` 表示原片在动而模块几乎不动），最后给同一时刻 5×5 点的取色对照。到原片在动的那个区域看 30fps 全分辨率帧，找出是什么在动（卷动、上浮、闪烁、旋转……），照着做。**只补原片里有的动作，不为了过门槛添加原片没有的动作。**
- 用户在对照页上审核。审核结论用 `opensay.py review --user-text` 记录用户原话，不代填。

## 7 准入

按 [统一消费准入](consumer-admission.md) 完成合同、两套内容测试、边界、跳时、反例和审核页。审核页附上覆盖表和对照报告的链接。

- 技术测试要按每个模块合同里声明的最短、最长时长各渲染一次，并检查最长版本后段不冻住（参考实现：`dark-type/verification/type-r1/test.mjs` 的 `max_tail` 检查）。没有文字参数的模块，第二套内容通过切换枚举选项来做。
- 并入已有模板时：模块共享的「整片氛围层」（统一运镜、光点、颗粒、镜头接力）要按模块关掉，复刻的镜头自带运镜和质感，叠上去就不像原片了。

## 常见错误

| 做法 | 结果 |
| --- | --- |
| 用每隔几秒一帧的缩略图拆原片 | 漏掉镜头、看错镜头 |
| 按「对比 / 流程 / 强调」这类表达关系建模块 | 风格像，镜头不像；原片的演示机制丢失 |
| 把「代码驱动预览」「改数驱动按钮」「时间轴驱动屏幕」做成一个素材槽 | 差距最大的一类 |
| 只学配色和字体，尺寸、节拍、时长凭印象 | 标题偏大，镜头偏长，节拍只有原片的 1/3 |
| 用色条、噪点、灰块当测试素材 | 看不出质感，也没法和原片对比 |
| 技术测试全过就交付 | 像不像没有证据 |
| 为了过「太静 / 结尾冻住」的门槛，给画面加原片没有的动作 | 指标过了，镜头不像；先用 `diff_regions.py` 找原片在动的地方 |
| 最长时长凭感觉写 12 秒、只测原片长度的用例 | 口播一长，镜头 3 秒后就冻住（本库实测：条形图、竖屏、水墨都出现过） |
| 只看画面不配声音 | 原片的打字声、大字落地声、切卡声全丢；第 13 项必填 |
| 凭记忆往合同里写原片时间 | 时间写错，甚至超出片长 |
