# X（x.com）草稿箱投递契约

X 视频帖草稿箱和其他平台一样，是 short-release 的可选投递落点之一。公开发布仍由用户最后自己操作。

## 当前状态

- 状态：`pending_login_and_adapter_validation`，不是 `READY`。`video-publisher` 目前没有 X 适配器。
- 不要把 `x` 硬塞进发布器的 `availablePlatforms/defaultPlatforms`：只加白名单、没有真实执行和验收，会让现有配置失效。
- 计划状态和执行结果分开记录。不能因为适配器还没接通，就在发布计划里漏掉 X，也不能把"计划投递"说成"已存草稿"。

## 接通步骤（用户登录后）

1. 用用户自己浏览器里已登录的 X 页面。账号要实际读出来核对，不猜用户名，不代替用户登录。
2. 按 `video-publisher` 的维护规范，增加 X 的独立适配器、内容包和配置校验、发布保护和状态回执。依据真实页面实现，不从其他平台猜控件或草稿机制。
3. 核对当前账号实际的文字、视频和附件限制。标题、简介、标签沿用用户提供的原文，不自动翻译、截断或改写；有限制就报告具体差异。
4. 在一次已授权的具体投递任务里，验证视频上传、文案、保存到草稿、从原生草稿列表重新打开。不点最终的发布或定时发布，不发私信。
5. 只有拿到稳定的草稿身份、重开后文字和视频一致、回执齐全，才算草稿交付成功。编辑框打开、上传动作完成、登录成功，都不等于草稿已保存。
6. 适配器实际验收通过后，才用发布器的配置命令把 X 加入可执行的默认平台，并保存真实的账号和能力状态（不保存 cookies 或 token）。

登录、平台配置、发布包授权，都不构成公开发布授权。不自动改走 MultiPost、API 或其他发布路线。
