# Sticker 流程契约

## 输入

- 用户的真人口播音频或视频，必须有。可以另附文案文件，用来校对字幕。
- 模板库：`.opensay` 包解压出的目录（里面有 `.opensay/opensay.py`）；设了 `OPENSAY_LIBRARY_ROOT` 的以它为准。
- 发布用的标题、简介、标签由用户提供，本技能不写。

## 输出规格

默认**完整正式预览与交付成片都是 1080p、30fps**。比例沿用本期已确认的；用户明确指定的规格优先，并记下用户的原话。

| 比例 | 宽 × 高，30fps |
|---|---|
| 16:9 横屏 | `1920x1080` |
| 9:16 竖屏 | `1080x1920` |
| 3:4 | `1080x1440` |
| 1:1 | `1080x1080` |

- 模板本身有固定画幅（例如竖屏 3:4）时，按模板画幅出。
- 其他比例以短边 1080 计算宽高。编码需要偶数时，另一边取最接近的偶数，并记下实际尺寸。
- 按用途可以升到 1080p60、4K30 或 4K60（4K 指短边 2160），但需要素材和模板都支持，并在编排里写明，不自动升级。真人和录屏优先保留原始帧率，不用重复帧冒充 60fps。
- 送审前和交付前，都用 `ffprobe` 读出实际的宽、高、帧率、帧数和时长，逐项核对，不能只凭文件名或参数判断。

### 规格核对工具

```bash
python3 <本技能目录>/scripts/output_profiles.py prepare \
  --plan <work>/episode_plan.json --stage full \
  --duration-seconds <全片实际声音时长> --out-dir <work>/full/render-config

python3 <本技能目录>/scripts/output_profiles.py check-media \
  --profile <work>/full/render-config/output-profile.json --video <work>/成片.mp4 \
  --out <work>/full/stage-media-check.json
```

`output_profiles.py` 不改计划、不改声音和时间轴，也不签署用户批准。

## 工作目录

由 `opensay.py start` 在模板库旁边的 `opensay-work/` 下新建，一期一个目录。只在这个目录里工作，不打开、不参考别的项目。主要产物：

```text
start.json                 # start 的回执：口播文件、时长、模板
voice/voice_timeline.json  # 词级时间轴，时间的唯一来源
voice/voice.wav
storyboard.json            # 你逐镜写的分镜
build-rN/                  # 每次编译的检查报告、逐镜自检表、计划
preview-rN.mp4             # 完整正式预览；用户确认后就是交付成片
```

## 审核关卡

| 关卡 | 需要用户明确确认 | 对应内容 |
|---|---|---|
| 选模板 | 是；用户已经指定的直接用 | 模板的动态预览、适用场景、真人和素材支持 |
| 完整正式预览 | 是，一次确认整片 | 全部镜头、完整旁白、字幕、配乐、音效 |
| 发布文字 | 由用户提供，不需要另行确认 | 标题、简介、标签原样交给 short-release |

不另设"样片审核"或"逐镜审核"。用户确认整片后直接进入成片与交接，不重复问同一版。

## 完整正式预览审核

送审的整片必须：

- 全部镜头用正式渲染、实际参数和实际素材，按最终宽高和帧率渲染，没有占位，没有缺镜头；
- 带完整真实旁白、字幕、配乐和音效，时间轴覆盖全长；
- 记录媒体路径、SHA256，以及分镜、模板版本、声音的哈希。

用户确认后，这一版就是交付成片，不再重渲染同一版。改了哪里，只复核受影响的部分。

## 时间轴规则

- `voice/voice_timeline.json` 是时间的唯一来源，SRT 只是格式转换。
- 只用可信的词级证据编排事件。没有就先补对齐，不平均分配时间。
- 镜头覆盖从 0 开始，到旁白结束，中间不留空洞、不重叠。
- 最终成片和旁白的时长差不超过 1 帧；超过就重排或重编码，不拉伸旁白。

## 失败处理

- 口播文件缺失或没有音轨：等用户给有效文件，不合成语音。
- 口播和文案对不上：先找出哪里不同，不估算没说的句子的时间。
- 分镜检查报错：逐条照 `fix` 改，改完重跑，不绕过检查。
- 渲染失败：保留已经完成的部分，修好后续跑，不拿旧成片冒充新版。
- QC 失败：不标记为定稿，不交给发布。

## 发布交接

顺序：口播 → 时间轴 → 选模板 → 编排与完整预览 → 用户确认 → 成片 QC → 交给 `short-release`。

交给 short-release 的内容：成片路径、SRT、QC 结果，以及用户提供的标题、简介、标签（原样）。用户没提供的，列出缺项等用户补，不代写。出包、投递哪些平台、草稿还是私密，都由 short-release 按用户设置执行。
