# 发布交接

Sticker 只负责把成片做好、确认好。出发布包、投递到各平台，由 `short-release` 技能负责（在你自己的技能目录里查找）。

## 工作台确认与发布包请求（2026-11-17）

Agent 在 `<项目>/workbench/release-materials.json` 引用本期标题、简介、标签、至少三种所需封面及实际投递落点，工作台只读展示。完整成片必须先导出并实际观看；只有用户本人点击产生的 `workbench/approvals/*.json` 才是页面确认证据。Agent 不代写确认/放行，不调用 `/__api/approve`、`/__api/override`，也不把实时可播或机器检查通过解释为用户确认。

当前字节与输入绑定的 `scope=film+release` 确认，或同版 `film` 与其后 `release` 补确认共同齐备后，沿用该副本现有的 QC、发布包与投递规则和用户授权；不额外索取同版出包许可。只有 `film` 时等待发布材料展示和补确认。视频、声音、模板源码、分镜或材料变更后校验受影响哈希，不能复用已失效的确认；若只改发布材料，不重渲未变视频。

用户在页面点击“请 Agent 生成发布包”会写 `workbench/requests/release-*.json`。Agent 看到请求或收到用户口头要求时，先核对引用的确认和当前成片/材料，再按既有 `short-release` 流程生成发布包；缺项如实报告。此请求不增加公开发布授权，不改变本副本既有平台、草稿/私密落点及素材预检要求。

## 交给 short-release 的内容

| 内容 | 来源 |
|---|---|
| 成片 | 用户确认过的完整正式预览，同一份文件，不重渲染 |
| 字幕 SRT | 从 `voice/voice_timeline.json` 转换 |
| QC 结果 | 用 ffprobe 读出的实际规格，以及完整解码检查 |
| 标题、简介、标签 | **用户提供，原样交过去**；缺了就列出缺项等用户补，不代写、不改写 |
| 封面 | 用户提供的，或用户确认过的 |

## 规则

- 标题、简介、标签全部由用户完成，Sticker 不生成、不润色、不补齐数量。
- 投递到哪些平台、存草稿还是私密，由 short-release 按用户的设置执行。Sticker 不直接上传任何平台。
- 公开发布由用户自己最后操作，不自动公开。
- 机器检查、自审和用户确认分开记录。用户没确认的内容，不能写成已确认。
