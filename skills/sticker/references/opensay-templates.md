# OpenSay 模板读取与编排约定

具体命令、词级事件、先检索后报素材缺口、修订和制作状态以[统一消费流程](consumer-workflow.md)为准。新模板与新增/修改模块必须通过同一 Builder 准入。

## 存储职责

- 模板库根目录：`.opensay` 包解压出的目录（里面有 `.opensay/opensay.py`）；设了 `OPENSAY_LIBRARY_ROOT` 的以它为准。每个直属文件夹就是一个模板，例如 `cartoon-explainer/`；不再套一层 `templates/`。
- 模板自己的 `capability.json` 用 `consumer_contract.path` 指向 `capability/consumer.v1.json`，消费合同保存当前语义、素材、模式、时长、事件、运行入口和验证证据；原生能力与旧入口保留，源码、依赖和许可证仍在该模板目录。
- Sticker 的 [template-capability.schema.json](template-capability.schema.json) 只校验数据结构，不提供或证明模板能力。
- 不维护全局 registry、adapter 或 modules 合同目录。模块合同保留在模板能力数据与本模板实际参数/素材契约中；不删除模板渲染所需的 `catalog/`、参数 schema 或 runtime。
- 每次选择/续做重新读取模板当前文件并与本期已确认哈希对比。能力变化更新模板目录，不把动态模块数据复制进 Sticker Skill。

使用库内共享 `discover/describe` 按需查询；`scripts/discover_opensay_templates.py` 兼容转发简短发现结果。共享工具与 Schema 放在 `.opensay/`，不保存全局模块数据。发现文件不等于验证能力。

## 固定顺序

```text
真人口播音频或视频（可另附文案）
→ opensay.py start：词级对齐与真实时间轴
→ 候选模板的动态预览
→ 用户确认模板（已经指定的直接用）
→ 按 QUICKSTART 逐镜写 storyboard.json，storyboard 检查通过
→ render-film 出完整正式预览
→ 用户确认整片 → 成片 QC → 交给 short-release
  覆盖不足时：本轮补齐预览，修改后只复核受影响内容
```

默认推荐三个合格候选；不足三个说明实际覆盖和缺口，只有一个可用时展示一个。模板选择与完整编排是先后两步；模块路由和路由动态预览是编排中的同一步，不另加逐镜确认。审核遵循[完整正式动态预览审核](pipeline-contract.md#完整正式动态预览审核)，通过后按[发布流程](release-flow.md)直接执行，不保留默认的独立样片/全片审核阶段。

本期若输入是文案和已经生成的 TTS，按 `voice_mode=tts` 沿用生成回执、声音和实测时间轴。真人音频/视频是另一条输入路线，不是提高画面质量的前提，不要求用户重录。

## 模块选择的证据

对每个候选模块至少核对：

- 画面表达的关系或变化是否与当前旁白吻合；
- `renderer_entry` 是否解析到真实实现，所选子阶段/单元是否可独立执行；
- `asset_slots` 是否在该模块实际读取 Logo、图片、截图、视频或 presenter，而不只是模板级存在同名字段；
- `presenter_modes` 与当前有无出镜方式是否吻合；
- 原生时长、可延长/可裁切边界与真实旁白区间是否兼容；
- `beat_input` 是否需要词级证据；无可信词证据时先补真实对齐，句级预览明确标注限制，不能等分伪造或声称词级要求已满足；
- `layout_signature`、`motion_signature` 是否描述了实际画面，预览中相邻/近期模块是否实质重复。

Schema 通过、模块名不同、源码文件存在、successful render 或一张截图，均不能单独证明上述能力。未验证能力标为未验证并记录缺口，不得宣称支持并直接通过正式动态预览审核。整个模板支持某类素材不代表其中所有模块都支持。

## 编排交付

分镜写在 `storyboard.json`，由 `opensay.py storyboard` 检查并编译出 `episode_plan.json`，其中记录所选模板路径/ID/版本、能力及源码哈希，以及逐镜的句子 ID、真实区间、视觉意图、实际 module ID/子阶段、参数、素材、节拍、解释机制和执行状态。

共享 `compile` 生成的 resolved-plan 和单镜请求是只读编译产物，随真源变化重建。动态预览必须沿用正式制作的 renderer、模块参数和 events。设计 `passed`、制作就绪、当前证据和用户确认分别核验。实际内容/素材缺失时明确标注；不要把占位窗口、示意 UI 或旧 Demo 冒充本期真实镜头。区分用于选型的通用 Demo、局部/低精度预览与本期完整正式动态成片：只有全部实际素材、最终分辨率/帧率、完整真实声轨/字幕/时间轴均已使用且整条已导出，才可合并成片审核；预览名称或镜头齐备本身不证明成片/QC完成。

正文与本期声音不为迁就模板而改写、变速或截尾。当前模块无法表达时记录 `needs_capture` / `needs_implementation` 与具体原因，再按用户既有授权处理；不自动用通用卡片兜底，也不为了“不重复”强塞无关图形。

用户确认模板后，完整编排、模块动态预览和整条正式媒体同轮审核，同时展示当前发布文案与封面。审核通过直接定稿/QC、出包并执行默认投递；覆盖不足先补齐本轮预览，只复核未覆盖或受影响内容。同版已确认内容继续复用，库更新或计划变化只复核实际受影响部分。

## 模板开发交接

视觉编排出现真实表达缺口或反复依赖同一载体时，调用 `opensay-template-builder` 技能（在你自己的技能目录里查找）诊断路由、素材、时序和模块能力。只有 Codex、Claude Code 承担模板创建/扩展；其他 Agent 继续消费现有模板或生成请求单，不能静默接管模板开发。双客户端入口与宿主检查属于工作流限制，同 OS 用户权限下不构成硬隔离。

交接采用该 Skill 的 `references/template-request.schema.json`：绑定目标模板 ID/版本/capability 哈希、本期唯一计划路径/哈希和问题 shot ID，说明缺口类型、原因与需要表达的变化。现有计划中的文案、真实句界、素材和 beats 继续作为真源，不把整份动态模板复制到 Skill。用户已在当前会话授权的扩展直接继续，不重复询问同一范围。

开发完成返回可独立渲染的实际模块、能力/源码新版本、素材与时序验证、受影响镜头的带原声同步动态草稿及回滚位置；只补能力声明或循环原生动作参考不算完成。更新同一本期计划和完整编排，回到原有同轮审核，不新增逐模块审批。机器校验、画面自审、用户确认分别保留真实状态；回到同一正式动态预览审核，补齐覆盖后一次确认定稿，再执行QC和发布流程；不另加样片或全片审核阶段。


## 本地源码归档候选

MotionGit等来源归档进OpenSay后，仍只扫描各模板自己的capability.json；来源收据、原生catalog、源码、声音、依赖锁和许可证都在该模板文件夹。外层个人包的凭据不属于模板资产，不随源码归档。已扩展模板的上游版本保留在本模板upstream/，不作为第二个当前模板。

Agent按本期文案的表达关系、画幅、出镜和素材需求综合推荐候选，解释匹配原因；读取recommendation.good_for/not_for、native_output、status和verification。source-archived-runtime-unverified、source-window-unverified等状态表示源码已归档，但动态预览或独立性待验证，不能自动排除其有用风格，也不能把它们写成已投产模块。展示时明确“候选，待实测”，依据具体镜头准备依赖和真实动态预览，再沿用原模板确认与完整编排审核；不新增源码归档审批或逐模块确认。

原生catalog的source时间窗仅是动作来源，不因有module ID就成为独立模块。静态gallery可辅助缩略图选择，但不能替代动态预览。BGM、音效、示例旁白按原角色和许可证分别保留；包内没有可用BGM时如实说明，不把示范TTS当作配乐。不同原生画幅/fps按本期output_profiles另行核验，不能把4:3或3:4自动当16:9/9:16。
