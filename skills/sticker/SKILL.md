# Sticker

以用户的真人口播为时间真源，用 OpenSay 模板把它做成视频。固定顺序：**口播文件 → 词级对齐与真实时间轴 → 选模板 → 逐镜编排与预览 → 完整正式预览审核 → 成片 → 交给 short-release**。

**本技能不写任何文字内容**：标题、口播文案、发布简介、标签都由用户自己写。缺了就列出来等用户补，不代写、不改写、不补全。

## 实时剪辑工作台（2026-11-17）

`start` 成功后，在模板库根目录运行 `node .opensay/workbench/server.mjs --project <本次项目绝对路径>`，把返回的 `url` 告诉用户。服务会用 Google Chrome 打开、复用已有实例；打不开浏览器时仍提供该 URL。工作台用 JavaScript，实现同模板片段切换、参数/触发词/切镜点/素材/文字缩放、撤销重做与实时播放；暂不跨模板切换。

打开工作台属于输入准备，不解除既有素材预检、必要用户素材收齐验收、真实时间轴与模板选择要求。条件满足后，Agent 每次修改前先重新读取 `storyboard.json`，保留用户已保存的调整；只修改本期分镜并调用共享 `storyboard` 命令。检查失败仍可查看已通过的镜头；占位、局部可播、仅旁白提示都属于制作状态，不能代替完整正式审核。

Agent 不得写入 `user_overrides`、`workbench/approvals/`，不得调用工作台 `/__api/override` 或 `/__api/approve` 接口。品味规则由用户在页面点击“我决定保留”并留痕，技术硬伤始终阻断；不从用户口头的泛指或机器 PASS 制造页面确认。复杂修改通过当前对话处理。

## 一句话直接开工

用户只说一句话、给一个口播音频或视频（可另附文案）时，不追问路径或步骤，直接做：

1. 找到 OpenSay 模板库，也就是 `.opensay` 包解压出的目录（里面有 `.opensay/opensay.py`）；设了环境变量 `OPENSAY_LIBRARY_ROOT` 的以它为准。
2. 在模板库根目录运行 `python3 .opensay/opensay.py start <口播文件> [--script <文案文件>] [--template <用户点名的模板>]`，由它完成词级对齐、建项目目录和分镜骨架，并在输出的 `next` 里给出后续命令。
3. 读模板库里的 `AGENTS.md` 和 `.opensay/QUICKSTART.md`，照做到出逐镜预览。`warnings` 原样告诉用户；模板没定时，把候选讲给用户选，不足三个就如实说明。
4. 用户逐镜提修改，就改 `storyboard.json` 再重跑。用户确认整片后，才进入成片与交接。
5. 只有文案、没有声音时：说明需要真人口播音频或视频，然后等待，不合成语音。

## 声音与真实时序

- 声音决定全片时长。不加速、不循环，不靠估算旁白来迁就模板。
- 时间来自 `start` 输出的 `voice/voice_timeline.json` 里的词级证据。没有可信的词级证据，就先补对齐，不平均分配时间、不猜词。
- 识别错了的专有名词用 `python3 .opensay/opensay.py retext` 改，不重新识别。拿不准的问用户。
- 用户给了文案时，文案只用来校对字幕和对齐，不改写它。实际说的和文案不一样时，以录音为准，并告诉用户哪里不同。
- 需要 SRT 时，用 `scripts/timeline_to_srt.py` 从真实时间轴转换。
- 混音参数见[混音标准](references/audio-mix.md)，数值以 `preferences/audio-mix.json` 为准。

细节见[声音入口](references/voice-inputs.md)。

## 输出规格

默认 1080p、30fps，比例沿用本期已确认的：16:9 为 1920×1080，9:16 为 1080×1920，3:4 为 1080×1440，1:1 为 1080×1080。模板本身是竖屏的，就按模板的画幅出。按用途可以升到 1080p60 或 4K，但要素材和模板都支持，并在编排里写明。用 `scripts/output_profiles.py` 核对实际媒体的宽、高、帧率，见[流程契约](references/pipeline-contract.md#输出规格)。

## 选模板与逐镜编排

1. 声音和时间轴就绪后，用 `python3 .opensay/opensay.py describe --template <模板> --brief` 读模板当前真实可用的模块，只用列出来的模块。每个直属文件夹就是一个模板，详见 [OpenSay 模板约定](references/opensay-templates.md)。
2. 给用户看候选模板的动态预览，说明它适合什么、支不支持真人出镜和素材。用户已经指定模板的，直接用。
3. 模板确定后，按 QUICKSTART 逐镜写 `storyboard.json`，跑 `storyboard`，按报错逐条改，直到通过，再 `render-film` 出完整预览。
4. 模块不够用、缺素材时，如实写进缺口，不拿通用卡片凑数。模板确实需要扩展时，交给 `opensay-template-builder` 技能（在你自己的技能目录里查找）。

## 完整正式预览审核

在工作台完成本关：先按最终规格“导出 MP4”，播放完整导出文件，再由用户本人点击确认。Agent 先准备只读发布材料清单 `<项目>/workbench/release-materials.json`：`{"title":"标题文件路径","description":"简介文件路径","tags":"标签文件路径","covers":["封面1路径","封面2路径","封面3路径"],"targets":["本期实际投递落点"]}`；相对路径基于项目目录。清单只引用本期真实材料，页面展示内容与哈希，标题/简介/标签原样保留。

用户点击生成的 `workbench/approvals/*.json` 可作为本关确认证据，须校验成片、storyboard、resolved-plan、episode_plan、模板源码、声音/时间轴、输出规格和所展示材料仍与当前版相符；保存点击时间、`scope`、备注原文、用户放行与编辑摘要。`scope=film+release` 覆盖已展示成片及发布材料；`scope=film` 只确认画面，待材料齐全并展示后由用户“补确认发布材料”（`scope=release`），与同版已有画面确认共同使用。导出中或导出后修改使相关旧确认失效；只复核受影响内容。实时 iframe 播放或局部预览本身不构成本关通过。

审核用的整片必须是：全部镜头、最终宽高和帧率、完整真实旁白、字幕、配乐和音效。没有占位，不用局部片段冒充整片。用户确认这一版后，它就是交付成片，不再重渲染同一版。

机器检查、你自己的视听自审、用户确认，三者分开记录。用户没确认，不能写成已确认。

## 交给 short-release

用户确认成片后，把成片、SRT、QC 结果交给 `short-release` 技能（在你自己的技能目录里查找），由它出发布包、投递到各平台。

**标题、简介、标签由用户提供，原样交过去**；缺了就列出来等用户补，本技能不生成。发布到哪些平台、草稿还是私密，都由 short-release 按用户设置执行。详见[发布交接](references/release-flow.md)。
